# 质检工具

点击 Edge 工具栏图标打开可拖动的独立浮窗。使用窗口标题栏移动位置，点击「收起」缩小窗口，再点「展开」继续。浮窗集中提供采集与复核、账号与工作入口。

在 Edge 工具栏中选择无锡、金坛、苏州、湖北或全部四站，然后点击「普通用户登录」「管理员登录」或「退出登录」。手动切换 GMQM 账号时，插件会通过平台菜单退出当前账号，再登录选定账号。「F.Brain 普通用户登录」打开公司和无锡 F.Brain，遇到登录页时使用单独保存的 F.Brain 普通账号。

## 加载

1. 在 Edge 地址栏输入 `edge://extensions/`。
2. 启用「开发人员模式」，点「加载解压缩的扩展」，选择本目录 `gmqm-edge`。
3. 在 Edge 的「扩展」菜单找到「质检工具」，可以固定到工具栏。

已加载过旧版时，在 `edge://extensions/` 找到扩展卡片并点「重新加载」。旧版的凭据经过口令加密，更新到 1.2.0 后请重新录入一次。

## 首次使用

点「设置账号」分别保存 GMQM 和 F.Brain 的普通账号。升级后，之前保存的普通账号继续用于 GMQM。需要手动切换到管理员时，可以分别设置对应站点的管理员账号。凭据保存在当前 Edge 配置的扩展本地存储中，重启 Edge 后也可直接使用。

若正在 GMQM 标签页，默认选中该基地。其他页面默认选「全部四站」。已有 GMQM 标签时工具优先复用其中一个。需要打开某站时，它会在后台新建标签。操作过程中关掉工具弹窗可稍后重新打开查看结果。

各站目前使用 HTTP，登录信息会提交到对应站点的原登录表单。工具需要机器能连到这些地址。若遇到站点提示、账号显示不一致或无法核对退出，使用结果行的「打开」回到对应标签检查。

## 采集与复核

在浮窗的「采集与复核」里选择任务、作业日期和站点。首次需要某站当天的数据时，逐站按 SOP 查询昨天和今天，保留平台默认时刻，导出全膜种、全 CCD 等级的原始判等表。核对行数与日期后，原表保存在当前 Edge 配置下。三项任务跨浮窗重启共用这张原表。采集按膜种及 CCD B 在本地筛 SN。若某站需要重新获取原表，可在文件列表移除该站当天的缓存后再运行。

- **过杀漏降复核**。点「一键生成过杀漏降 Excel」，按站点、膜种及过杀或漏检标记统计全等级数据。工作簿包含「复核汇总」和「子卷明细」，人工判断留空。可下载文本汇总，回查按钮会在该站自动判等页填写生产时间、膜种、标记和对应 SN 后查询。
- **蚊虫碎膜采集**。点「一键采集蚊虫碎膜」后自动查询四站、核对 CCD B 导出、用去重子卷 SN 建库和提交采集，设置判等区域、AI 复判、CCD B 和碎膜、蚊虫两个缺陷。入库后逐一核对图库中出现的膜种，包括点涂膜。已有图库可用「仅补标签」补齐六类标签，无需重新导出或采集。
- **分类图库采集**。自动处理所选的金坛、苏州和湖北。平台查询及导出通过核对后，创建或复用图库、填入对应膜种的 CCD B 子卷 SN，按 SOP 提交采集并核实入库。迭代图库只建库。成功入库的张数自动填入，可下载当天统计 TXT。

单膜种且日期核对通过的原始导出，可以按 SOP 文件名重新下载。导入文件和录入的张数保留在当前浮窗。运行中可收起浮窗，关闭浮窗会中断工具对平台任务的跟踪。过杀漏降的图像判断、蚊虫碎膜人工分类在平台页面完成。
## 模型部署

浮窗的「模型部署」页签提供「一键运行」和六个可分别启动的阶段。「模型日期」默认北京时间当天，按该日期查询模型的创建时间。部署与 GMQM 验证数据使用实际作业当天。首次使用时，分别保存两个平台的普通账号，选择本地的「更新模型」目录，并勾选要打包与验证的 GMQM 基地。遇到登录页时，插件使用对应平台的普通账号登录，再打开原来的工作页面。

选好模型日期后点「一键运行」。当天用同一个模型日期重跑会沿用已选模型、复用通过校验的 ZIP、跳过已打包或验证的基地。GMQM 打包时保留当前提交页，等对应的新 MAR 出现后再继续。超时后可用同一个按钮继续核对该版本。

1. 从两个 F.Brain 查找创建于所选模型日期且训练成功的模型。同类取当天最新版本，查到的模型默认全选。未配置打包文件名的模型也会列出。进入下一阶段前，需要勾选的模型全部完成当前阶段。
2. 部署最新模型为 ONNX，核对 285×285。查到当天同名、同版本记录时先等待平台状态。
3. 在部署成功的条目中选择「下载模型格式为.onnx」，等待浏览器完成下载，再按界面显示的目录归档原包。目录从作业日对应的「更新模型\mmdd\模型」开始。选作业日前一天的模型可复用旧版目录，其他模型日期各用一个以日期命名的子目录。
4. 解压并按 SOP 重命名。成品 ZIP 根目录只放对应的 ONNX 和 JSON，并对原包、解压文件和成品分别核对 SHA-256。
5. 等各基地模型列表返回实际 MAR 记录，按最近一版的版本末段加一。根据对应方案的模型文件名匹配新 ZIP，其他槽位继承上一版，逐项显示来源设置进度，提交打包并等待新条目出现。
6. 对当前勾选且尚无本批 MAR 的基地补打包，从各基地全量判等表抽取 200 个不重复的有效子卷 SN，在对应模型的验证配置弹窗提交。到验证任务列表查看状态，并在详情核对同一批 SN 后记录结果。

点击「暂停」后，工具在当前平台操作返回时停止。切换基地勾选时，打包和验证进度按当前勾选更新，下次运行使用这次勾选，同一作业日会保留勾选。启动同一个阶段会复用当前模型日期的已记录结果并跟进未完成的任务。浮窗关闭后可重新打开并从保留下来的记录继续。已有原包可在模型页签按模型导入，然后单独运行 ZIP 整理和后续阶段。
